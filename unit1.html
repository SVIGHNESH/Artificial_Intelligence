01Definition of AI

Artificial Intelligence is the study and design of agents that perceive their environment and take actions that maximise their chance of achieving goals.

Russell & Norvig arrange definitions of AI along two axes: thinking vs acting, and human-like vs rational.

ThinkingThinking Humanly
Cognitive modelling		Thinking Rationally
Laws of thought (logic)
ActingActing Humanly
Turing Test		Acting Rationally

Acting humanly: the Turing Test (1950)

A human interrogator chats through text with a machine and a human. If the interrogator cannot reliably tell which one is the machine, the machine passes.

To pass, a computer needs four capabilities:

  • Natural Language Processing to communicate.
  • Knowledge Representation to store what it knows or hears.
  • Automated Reasoning to answer questions and draw new conclusions.
  • Machine Learning to adapt to new situations and detect patterns.

The Total Turing Test adds a video signal and passing physical objects, so it also needs Computer Vision and Robotics.

Thinking humanly: cognitive modelling

Build programs whose internal steps match how humans think. Theories come from introspection, psychological experiments and brain imaging. Example: Newell and Simon's GPS (General Problem Solver) compared its reasoning trace with human subjects solving the same problems.

Thinking rationally: laws of thought

Based on Aristotle's syllogisms and formal logic: "Socrates is a man; all men are mortal; therefore Socrates is mortal."

Two problems: informal and uncertain knowledge is hard to write in logic, and solving a problem "in principle" is very different from solving it in practice (computation blows up).

Acting rationally: the rational agent

A rational agent acts to achieve the best outcome, or the best expected outcome when there is uncertainty. Modern AI prefers this approach because it is more general than the laws of thought (correct inference is only one way to act rationally) and it is mathematically well-defined, unlike "behave like a human".

05Intelligent agents

An agent is anything that perceives its environment through sensors and acts on it through actuators.

Key terms

Percept
The agent's perceptual input at one instant.
Percept sequence
The complete history of everything the agent has ever perceived.
Agent function
An abstract mathematical mapping from percept sequences to actions, f : P* → A.
Agent program
The concrete code that implements the agent function on a physical system.
Architecture
The computing device with sensors and actuators. Agent = Architecture + Program.
AgentSensorsActuators
HumanEyes, ears, nose, skinHands, legs, vocal tract

Rationality: characteristics of an intelligent agent

Definition of a rational agent

For each possible percept sequence, a rational agent selects an action that is expected to maximise its performance measure, given the evidence from the percept sequence and whatever built-in knowledge it has.

What is rational at any moment depends on four things:

  1. The performance measure that defines success.
  2. The agent's prior knowledge of the environment.
  3. The actions the agent can perform.
  4. The agent's percept sequence to date.
Rational ≠ Omniscient

An omniscient agent knows the actual outcome of its actions. A rational agent maximises expected performance. Crossing the road after looking both ways is rational even if a falling aircraft door hits you.

Information gathering

Doing actions to get useful future percepts (looking before crossing, exploring an unknown map) is part of being rational.

Learning

A rational agent should learn as much as possible from what it perceives, not only rely on the designer's prior knowledge.

Autonomy

An agent is autonomous when its behaviour depends on its own experience. A dung beetle that keeps plugging a nest after the ball is removed lacks autonomy.

Other characteristics often asked in exams: situatedness (lives inside an environment), reactivity (responds in time to changes), pro-activeness (goal-directed, takes initiative), social ability (communicates with other agents) and adaptability.

08Types of agents (agent architectures)

Five basic agent programs, in increasing order of generality. Each one adds a capability that the previous one lacks.

1. Simple reflex agent

Sensors→What the world is like now→Condition-action rules→What action to do→Actuators
  • Acts only on the current percept and ignores history.
  • Uses condition-action (if-then) rules: if car-in-front-is-braking then initiate-braking.
  • Works correctly only if the environment is fully observable.
  • In partially observable worlds it can fall into infinite loops. Randomising actions helps.
function SIMPLE-REFLEX-AGENT(percept):
    state ← INTERPRET-INPUT(percept)
    rule  ← RULE-MATCH(state, rules)
    return rule.ACTION

Examples: thermostat, automatic door, basic vacuum cleaner.

2. Model-based reflex agent

Sensors→Internal state + model of world→Condition-action rules→Actuators
  • Keeps an internal state tracking the parts of the world it cannot see right now.
  • Needs a transition model (how the world changes on its own and due to my actions) and a sensor model (how world state shows up in percepts).
  • Handles partially observable environments.
function MODEL-BASED-REFLEX-AGENT(percept):
    state ← UPDATE-STATE(state, action, percept, transition_model, sensor_model)
    rule  ← RULE-MATCH(state, rules)
    action ← rule.ACTION
    return action

Example: a car that remembers a vehicle is in its blind spot even when the mirror no longer shows it.

3. Goal-based agent

State + model→"What will happen if I do A?"→Goals→Action
  • Has goal information describing desirable situations.
  • Thinks ahead using search and planning.
  • More flexible: change the goal and the behaviour changes without rewriting rules.

Example: a navigation app asked to reach Lucknow Charbagh station.

4. Utility-based agent

State + model→"What will happen if I do A?"→"How happy will I be?" (utility)→Action
  • Goals give only a binary happy/unhappy; a utility function maps each state to a real number.
  • Needed when goals conflict (speed vs safety) or when no goal can be reached with certainty, so likelihood must be weighed against importance.
  • A rational utility-based agent maximises expected utility.

Example: a taxi choosing a route that is fast, safe and cheap at the same time.

5. Learning agent

Performance element
Selects external actions.
Critic
Tells how well the agent is doing against a fixed performance standard.
Learning element
Uses the critic's feedback to improve the performance element.
Problem generator
Suggests exploratory actions that lead to new, informative experiences.

Example: a spam filter that improves when users click "Not spam", or a self-driving car that learns from driver takeovers.

Agent = Architecture + Program. The program must suit the architecture: a program that says "Walk" only makes sense if the architecture has legs.

Atomic

Used in: search, game playing
Factored

State is a set of variables with values.

Used in: CSP, propositional logic, Bayes nets
Structured

State has objects and relationships between them.

Used in: first-order logic, NLP

09Problem-solving agents

A problem-solving agent is a goal-based agent that uses an atomic representation and searches for a sequence of actions that reaches the goal.

Four phases

1. Goal formulation→2. Problem formulation→3. Search→4. Execution
function SIMPLE-PROBLEM-SOLVING-AGENT(percept):
    state ← UPDATE-STATE(state, percept)
    if seq is empty:
        goal    ← FORMULATE-GOAL(state)
        problem ← FORMULATE-PROBLEM(state, goal)
        seq     ← SEARCH(problem)
        if seq = failure: return null-action
    action ← FIRST(seq);  seq ← REST(seq)
    return action

While executing, this agent ignores its percepts because it trusts the plan. This is called open-loop execution and is safe only in fully observable, deterministic, known environments. Otherwise the agent should use closed-loop execution and keep checking its percepts.

Components of a well-defined problem

Five components (write all five in every formulation answer)
  1. Initial state: where the agent starts, e.g. In(Arad).
  2. Actions: ACTIONS(s) returns the actions applicable in state s.
  3. Transition model: RESULT(s, a) returns the state reached by doing a in s.
  4. Goal test: decides whether a state is a goal.
  5. Path cost: sum of step costs c(s, a, s′).
State space
All states reachable from the initial state; forms a graph.
Solution
An action sequence leading from the initial state to a goal state.
Optimal solution
The solution with the lowest path cost.
Abstraction
Removing irrelevant detail (weather, radio station) so the problem becomes tractable. A good abstraction removes as much detail as possible while keeping the solution valid.

8-queens

Place 8 queens on a chessboard so that no two attack each other.

  • Incremental formulation: start empty and add one queen at a time. Naive version has about 1.8 × 10¹⁴ sequences. Placing each queen in the leftmost empty column where it is not attacked cuts this to 2,057 states.

Missionaries and cannibals

Three missionaries and three cannibals must cross a river with a boat that holds one or two people. Cannibals must never outnumber missionaries on either bank where missionaries are present.

★Case studies & scenarios

Try each one on paper first, then open the model answer.

Case 1 · Smart traffic signal

A city wants an AI system that controls the traffic lights at a busy junction using cameras, to reduce waiting time. Give the PEAS, classify the environment and suggest a suitable agent type.

Model answer
PAverage waiting time, queue length, accidents, priority for ambulances
EJunction, vehicles, pedestrians, weather, time of day
ASignal lights (red/yellow/green), countdown timer display
SCCTV cameras, induction-loop sensors, emergency vehicle GPS/siren detection

Environment: partially observable (fog, occluded lanes), multi-agent (drivers), stochastic (driver behaviour is unpredictable), sequential (a long green now builds a queue on the other road), dynamic, continuous, known rules.

Agent type: a utility-based learning agent. A simple reflex agent with fixed timers cannot adapt to traffic. The goals conflict (main road vs side road, cars vs pedestrians), so a utility function is needed to balance them. Traffic patterns change over months, so a learning element should tune the timings from feedback.

Case 2 · Online exam proctoring

A university uses webcam AI to flag cheating during online exams. Give the PEAS and environment, and justify the agent type.

Model answer
PCheating cases correctly flagged, few false alarms, privacy compliance
EStudent, room, laptop, exam software
AWarning pop-ups, reports to invigilator, screen lock
SWebcam, microphone, screen capture, keystrokes, browser tab-switch events

Environment: partially observable (camera sees only part of the room), multi-agent in an adversarial sense (a cheating student acts against the agent), stochastic, sequential over the session, dynamic, continuous (video).

Agent type: at least model-based reflex, because a single frame is not enough; it must remember "the student looked away 5 times in 2 minutes". Ideally a learning agent so that invigilator feedback on false alarms reduces them over time.

Case 3 · Agricultural drone

A drone sprays pesticide only on the infected parts of a field. Design the agent.

Model answer
P% of infected area treated, pesticide used, battery used, crop damage avoided
EField, crops, wind, obstacles (trees, poles), other drones
APropellers, spray nozzle, camera gimbal
SMultispectral camera, GPS, wind sensor, altimeter, battery sensor

Environment: partially observable, single agent (or cooperative multi-agent with a drone fleet), stochastic (wind), sequential, dynamic, continuous.

Agent type: goal-based + utility-based. It must plan a path covering all infected patches (goal) while minimising pesticide and battery (utility). Problem formulation: state = (position, battery, tank level, set of untreated patches); actions = fly to next patch, spray, return to base; goal = no untreated patch left; path cost = distance + pesticide used.

Case 4 · Oscillating vacuum

A simple reflex vacuum cleaner with no location sensor keeps moving Left-Right forever in a clean room. Why does this happen, and how would you fix it?

Model answer

The agent only perceives [Clean] and cannot tell whether it is in A or B. The same rule fires every time, so it loops forever. This is the classic failure of simple reflex agents in a partially observable environment.

Fix 1: randomise the move (Left or Right with probability 0.5); it will eventually cover both squares.

Fix 2 (better): use a model-based reflex agent that remembers which squares it has already cleaned and does NoOp once all are clean.

Case 5 · Is it rational?

A self-driving car brakes hard for a plastic bag on the road and is rear-ended. Was its action rational?

Model answer

Rationality is judged on expected performance given the percept sequence, not on the actual outcome. If the percepts could not distinguish the bag from a small animal or child, braking maximised expected safety, so the action was rational but not omniscient.

However, a better design would gather more information (LIDAR density, object tracking over frames), weigh the risk of the car behind in its utility function, and learn from such cases.

Case 6 · Hospital triage chatbot

A hospital deploys a chatbot that asks patients about symptoms and decides whether they should see a doctor today, book a later appointment, or go to emergency. Classify the environment and pick an agent type.

Model answer

PEAS: P = correct urgency level, patient safety, waiting time, doctor workload; E = patients, hospital schedule, doctors; A = questions displayed, recommendations, appointment booking; S = typed or spoken answers, vitals from wearables, medical records.

Environment: partially observable (patients may describe symptoms wrongly), single agent (patient is part of the environment), stochastic, sequential (each answer decides the next question), static during a conversation, discrete (question choices) but symptoms may be continuous values.

Agent type: utility-based, because missing an emergency costs far more than an extra visit, so outcomes must be weighed, not just a yes/no goal. Add learning from doctors' final diagnoses.

Answer template for any scenario
  1. One line: who the agent is and what it is trying to do.
  2. PEAS table.
  3. Environment classification with a short reason for each property.
  4. Agent type chosen, and why simpler types fail.
  5. Problem formulation (state, actions, transition, goal, cost) if planning is involved.
  6. Challenges and ethics (privacy, bias, safety) for extra marks.

12Quick revision (2-mark answers)

  • AI: study of agents that receive percepts and act to maximise a performance measure.
  • Turing Test: behavioural test of machine intelligence proposed by Alan Turing in 1950.
  • Agent function vs program: the function is an abstract mapping; the program is its implementation.
  • Rational agent: maximises expected performance given percepts and prior knowledge.
  • Omniscience: knowing actual outcomes; impossible and not required for rationality.
  • Autonomy: behaviour determined by the agent's own experience.
  • PEAS: Performance measure, Environment, Actuators, Sensors.
  • Semi-dynamic: environment doesn't change with time but the score does (chess with a clock).
  • Episodic: each decision is independent of earlier ones (defect detection on a conveyor).
  • Utility function: maps a state to a real number describing how desirable it is.
  • Abstraction: removing detail from a representation to make problem solving tractable.
  • Dartmouth 1956: birth of AI; term coined by John McCarthy.
  • Open-loop: executing a plan while ignoring percepts.
  • State space: set of all states reachable from the initial state.
