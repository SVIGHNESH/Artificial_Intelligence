02Uninformed (blind) search

Uninformed strategies know only the problem definition. They can generate successors and test for the goal, but have no idea which non-goal state is "closer" to the goal.

Breadth-First Search (BFS)

  • Expands the shallowest unexpanded node first, level by level.
  • Frontier is a FIFO queue.
  • Goal test can be done when a node is generated, which saves one level of work.
  • Complete if b is finite. Optimal when all step costs are equal.
  • Time and space O(bd). Memory is the big problem: at b = 10, d = 12, BFS needs about 10 terabytes.
StepExpandFrontier (queue) after
1AB, C
2BC, D, E
3CD, E, F, G ← goal generated

Order of visiting: A → B → C → D → E → F → G. Path found: A → C → G.

Uniform-Cost Search (UCS)

  • Expands the node with the lowest path cost g(n). Frontier is a priority queue ordered by g.
  • Goal test is done when a node is expanded, not when generated, otherwise a costlier path may be returned.
  • Complete and optimal if every step cost ≥ ε > 0. Time and space O(b1+⌊C*/ε⌋).
  • BFS is UCS with all step costs equal. UCS is Dijkstra's algorithm stopped at the goal.

Example (Sibiu → Bucharest): Sibiu generates Rimnicu Vilcea (80) and Fagaras (99). Expand RV (80) → Pitesti (177). Expand Fagaras (99) → Bucharest (310). Expand Pitesti (177) → Bucharest (278), which replaces 310 in the frontier. Expand Bucharest (278): goal. UCS returns Sibiu → RV → Pitesti → Bucharest = 278, not the 310 path it generated first.

Depth-First Search (DFS)

  • Expands the deepest unexpanded node first. Frontier is a LIFO stack (or recursion).
  • Not complete in infinite spaces or with loops (tree-search version). Not optimal.
  • Time O(bm), which is terrible if m ≫ d.
  • Space only O(bm). This linear memory is its main advantage.

Order of visiting: A → B → D → E → H → C → F → G. Path found: A → C → G, but only after exploring the whole left subtree.

Depth-Limited Search (DLS)

  • DFS with a depth limit ℓ: nodes at depth ℓ are treated as having no children.
  • Solves DFS's infinite-path problem.
  • Incomplete if ℓ < d, non-optimal if ℓ > d. Time O(bℓ), space O(bℓ).
  • Can fail in two ways: failure (no solution) or cutoff (no solution within the limit).
  • The limit can come from knowledge of the problem, e.g. Romania has 20 cities so any solution has depth ≤ 19. The diameter (any city reachable from any other in 9 steps) gives a better limit.

Iterative Deepening DFS (IDDFS / IDS)

  • Runs DLS with limits 0, 1, 2, 3, … until a goal is found.
  • Combines the benefits of BFS and DFS: complete and optimal (unit costs) like BFS, with O(bd) memory like DFS.
  • Time O(bd). The repeated work looks wasteful, but most nodes are at the bottom level, so it adds little.
  • Preferred uninformed method when the search space is large and the depth of the solution is unknown.

Why the repeated work is cheap

N(IDS) = d·b + (d−1)·b² + … + 1·bd

For b = 10, d = 5: N(IDS) = 50 + 400 + 3,000 + 20,000 + 100,000 = 123,450, while N(BFS) = 10 + 100 + 1,000 + 10,000 + 100,000 = 111,110. Only about 11% extra.

Bidirectional search

  • Runs two searches, one forward from the start and one backward from the goal, and stops when they meet.
  • Time and space O(bd/2). For b = 10, d = 6: 2 × 10³ = 2,000 nodes instead of 10⁶.
  • Needs actions that can be reversed and a single, explicit goal state (hard for "checkmate" style goals).

04Informed (heuristic) search

Informed search uses problem-specific knowledge in the form of a heuristic function h(n): the estimated cost of the cheapest path from node n to a goal. h(goal) = 0. Nodes are chosen using an evaluation function f(n); the algorithm is called best-first search.

Greedy best-first search

  • Expands the node that appears closest to the goal: f(n) = h(n).
  • Fast when the heuristic is good, but not optimal and not complete (tree-search version can loop, e.g. Iasi → Neamt → Iasi …).
  • Worst case time and space O(bm).

05A* search

Evaluation function

f(n) = g(n) + h(n)

g(n) = actual cost from start to n; h(n) = estimated cost from n to goal; so f(n) = estimated cost of the cheapest solution through n.

Key point to write

At step 4 Bucharest was already in the frontier with f = 450, but A* did not stop, because the goal test is applied on expansion. Pitesti (417) was cheaper, and it led to a better Bucharest (418). This is why A* is optimal while greedy is not.

Conditions for optimality

Admissible heuristic

h(n) ≤ h*(n) for every n, where h* is the true cost to the goal. It never overestimates. Straight-line distance is admissible because the straight line is the shortest possible path. A* tree search is optimal if h is admissible.

Consistent (monotonic) heuristic

h(n) ≤ c(n, a, n′) + h(n′) for every successor n′ (triangle inequality). Then f never decreases along a path. A* graph search is optimal if h is consistent. Every consistent heuristic is admissible.

Properties of A*

  • Complete if b is finite and step costs ≥ ε > 0.
  • Optimal under the conditions above.
  • Optimally efficient: no other optimal algorithm using the same heuristic is guaranteed to expand fewer nodes.
  • Expands all nodes with f(n) < C*, some with f(n) = C*, none with f(n) > C*, so parts of the tree are pruned.
  • Main drawback: memory. It keeps every generated node, so it usually runs out of space before time.

Memory-bounded variants

  • IDA* (Iterative Deepening A*): iterative deepening where the cutoff is the f-cost instead of depth. Each round uses the smallest f that exceeded the previous cutoff.
  • RBFS (Recursive Best-First Search): linear space, remembers the best alternative f-value.
  • SMA* (Simplified Memory-bounded A*): runs A* until memory is full, then drops the worst leaf and backs up its value to the parent.

Effective branching factor b*

If A* generates N nodes for a solution at depth d, then b* is the branching factor a uniform tree of depth d would need to contain N + 1 nodes: N + 1 = 1 + b* + (b*)² + … + (b*)d. A good heuristic gives b* close to 1.

Inventing heuristics

  • Relaxed problems: remove constraints from the actions. The exact cost of a relaxed problem is an admissible heuristic for the original.
    • "A tile can move anywhere" → h₁.
    • "A tile can move to any adjacent square, even if occupied" → h₂.
  • Pattern databases: store exact costs of solving sub-problems (e.g. tiles 1-4).
  • Learning from experience (features such as number of misplaced tiles and pairs of adjacent tiles).
  • Combining: h(n) = max(h₁, h₂, …, hk) is admissible if each is, and dominates all of them.

07Local search & optimisation: hill climbing

In many problems the path does not matter, only the final state (8-queens, timetabling, VLSI layout, TSP tour). Local search keeps only the current state and moves to neighbours. It uses very little memory and works in huge or continuous spaces. The goal is to find the global maximum of an objective function (or global minimum of a cost).

Hill climbing (steepest ascent)

Repeatedly move to the neighbour with the highest value; stop when no neighbour is better. It is "greedy local search", like climbing Everest in thick fog with amnesia.

function HILL-CLIMBING(problem):
    current ← problem.INITIAL-STATE
    loop:
        neighbour ← highest-valued successor of current
        if neighbour.VALUE ≤ current.VALUE: return current
        current ← neighbour

Problems with hill climbing

Local maxima

A peak higher than its neighbours but lower than the global maximum. The algorithm gets stuck.

Plateau

A flat area: either a flat local maximum or a shoulder from which progress is possible. The search wanders randomly.

Ridges

A sequence of local maxima that is hard to climb because no single move goes uphill along the ridge.

On 8-queens, steepest-ascent hill climbing gets stuck 86% of the time and solves only 14% of random instances, but it is fast: about 4 steps when it succeeds and 3 when it gets stuck. Allowing up to 100 sideways moves raises success to 94%.

Variants

VariantIdea
Stochastic hill climbingPick randomly among uphill moves, weighted by steepness
First-choice hill climbingGenerate successors randomly and take the first one that is better. Good when there are thousands of successors.
Random-restart hill climbing"If at first you don't succeed, try again." Run from random start states until a goal is found. Complete with probability 1. If each run succeeds with probability p, expected restarts = 1/p (≈ 7 for 8-queens).
Sideways movesAllow moves to equal-valued neighbours to escape shoulders (with a limit to avoid infinite loops on flat maxima)

Other optimisation methods

  • Local beam search: keep k states instead of one. At each step generate all successors of all k states and keep the best k. Information is shared between the k searches, unlike k independent restarts. Stochastic beam search picks the k successors randomly, weighted by value, to keep diversity.
  • Genetic algorithms: a population of k states (strings). Each generation: evaluate fitness → selection (fitter states more likely to reproduce) → crossover (combine two parents at a random point) → mutation (random small change). For 8-queens, a state is a string like 24748552 (row of the queen in each column) and fitness is the number of non-attacking pairs (max 28).

08Simulated annealing

Hill climbing never goes downhill, so it is incomplete. A random walk is complete but very inefficient. Simulated annealing combines the two, inspired by annealing in metallurgy: metal is heated and then cooled slowly so it settles into a low-energy crystal state.

function SIMULATED-ANNEALING(problem, schedule):
    current ← problem.INITIAL-STATE
    for t = 1 to ∞:
        T ← schedule(t)
        if T = 0: return current
        next ← a randomly selected successor of current
        ΔE ← next.VALUE − current.VALUE
        if ΔE > 0: current ← next                          // good move: always accept
        else: current ← next only with probability eΔE/T   // bad move: sometimes accept
Acceptance probability for a bad move

P = eΔE / T (ΔE < 0)

  • The worse the move (more negative ΔE), the lower the probability.
  • The higher the temperature T, the more likely bad moves are accepted.
  • T starts high (exploration) and decreases over time (exploitation).
  • If T decreases slowly enough, the algorithm finds the global optimum with probability approaching 1.
Worked example: ΔE = −5Probability of accepting
T = 100e−0.05 ≈ 0.95
T = 10e−0.5 ≈ 0.61
T = 1e−5 ≈ 0.0067

Used in VLSI layout, factory scheduling, TSP and other large optimisation problems.

Hill climbing

Only uphill moves, deterministic, gets stuck at local maxima, fast.

Simulated annealing

Accepts downhill moves with a probability that drops over time, escapes local maxima, slower but finds better solutions.

09Constraint Satisfaction Problems (CSP)

A CSP uses a factored representation: a state is a set of variables with values, and a solution is an assignment that satisfies every constraint.

Definition: three components
  • X = set of variables {X₁, …, Xₙ}.
  • D = set of domains {D₁, …, Dₙ}, one per variable.
  • C = set of constraints that specify allowed combinations of values.

An assignment is consistent if it violates no constraint and complete if every variable has a value. A solution is consistent and complete.

Example: map colouring of Australia

  • Variables: WA, NT, Q, NSW, V, SA, T.
  • Domains: {red, green, blue} for each.
  • Constraints: adjacent regions differ: WA≠NT, WA≠SA, NT≠SA, NT≠Q, SA≠Q, SA≠NSW, SA≠V, Q≠NSW, NSW≠V.
  • One solution: WA=red, NT=green, SA=blue, Q=red, NSW=green, V=red, T=red (T can be anything).

Backtracking search

DFS that assigns one variable at a time and backtracks as soon as a variable has no legal value left.

function BACKTRACK(assignment, csp):
    if assignment is complete: return assignment
    var ← SELECT-UNASSIGNED-VARIABLE(csp)            // MRV, degree
    for each value in ORDER-DOMAIN-VALUES(var)       // LCV
        if value is consistent with assignment:
            add {var = value}
            inferences ← INFERENCE(csp, var, value)  // forward checking / AC-3
            if inferences ≠ failure:
                result ← BACKTRACK(assignment, csp)
                if result ≠ failure: return result
        remove {var = value} and inferences
    return failure

Heuristics that make backtracking fast

HeuristicQuestion it answersRule
MRV (Minimum Remaining Values), "fail-first"Which variable next?Pick the variable with the fewest legal values left
Degree heuristicTie-breaker for MRVPick the variable involved in the most constraints with unassigned variables (SA first in Australia, degree 5)
LCV (Least Constraining Value)Which value to try first?Pick the value that rules out the fewest choices for neighbours

Memory trick: choose the variable that fails first (MRV) but the value that fails last (LCV).

Inference: forward checking

After assigning X, remove inconsistent values from the domains of X's unassigned neighbours. If some domain becomes empty, backtrack immediately.

Forward checking misses one thing: after Q = green, NT and SA are both {B} and adjacent, which is already impossible. Arc consistency catches this earlier.

Arc consistency (AC-3)

  • Arc X → Y is consistent if for every value of X there is some value of Y that satisfies the constraint.
  • AC-3 keeps a queue of arcs. For each arc (X, Y) it deletes unsupported values from X; if X's domain changed, all arcs (Z, X) are added back to the queue.
  • If any domain becomes empty, there is no solution.
  • Complexity O(c·d³) for c binary constraints and domain size d.

Local search for CSP: min-conflicts

Start with a complete (possibly invalid) assignment. Repeatedly pick a conflicted variable and give it the value that causes the fewest conflicts. Solves the million-queens problem in about 50 steps on average.

10Game playing: minimax

Games are adversarial search problems in competitive multi-agent environments. Classical game AI studies deterministic, two-player, turn-taking, zero-sum games of perfect information (chess, tic-tac-toe).

Formal definition of a game

S₀
Initial state.
PLAYER(s)
Which player moves in state s (MAX or MIN).
ACTIONS(s)
Legal moves in s.
RESULT(s, a)
Transition model.
TERMINAL-TEST(s)
True when the game is over.
UTILITY(s, p)
Final numeric value for player p, e.g. +1 win, 0 draw, −1 loss.
Minimax value

MINIMAX(s) = UTILITY(s) if terminal
maxa MINIMAX(RESULT(s,a)) if PLAYER = MAX
mina MINIMAX(RESULT(s,a)) if PLAYER = MIN

MAX picks the move with the highest value assuming MIN plays optimally and tries to minimise MAX's score.

function MINIMAX-DECISION(state):
    return argmaxa ∈ ACTIONS(state) MIN-VALUE(RESULT(state, a))

function MAX-VALUE(state):
    if TERMINAL-TEST(state): return UTILITY(state)
    v ← −∞
    for each a in ACTIONS(state): v ← MAX(v, MIN-VALUE(RESULT(state, a)))
    return v

function MIN-VALUE(state):
    if TERMINAL-TEST(state): return UTILITY(state)
    v ← +∞
    for each a in ACTIONS(state): v ← MIN(v, MAX-VALUE(RESULT(state, a)))
    return v

Properties of minimax

  • Complete if the tree is finite; optimal against an optimal opponent.
  • Time O(bm), space O(bm) (depth-first).
  • For chess b ≈ 35 and m ≈ 100, so exact minimax is impossible. Real programs cut off the search.

Imperfect real-time decisions

  • Replace TERMINAL-TEST with a CUTOFF-TEST (depth limit, usually with iterative deepening so a move is ready when time runs out).
  • Replace UTILITY with an evaluation function EVAL(s) that estimates the value of a position. Typical form: weighted linear sum EVAL(s) = w₁f₁(s) + w₂f₂(s) + … + wₙfₙ(s), e.g. chess material: pawn 1, knight/bishop 3, rook 5, queen 9.
  • Quiescence search: keep searching "noisy" positions (pending captures) until they are quiet before applying EVAL.
  • Horizon effect: the program pushes an unavoidable bad event beyond its search depth with delaying moves, so it doesn't see it.

11Alpha-beta pruning

Alpha-beta returns the same move as minimax but skips branches that cannot affect the final decision.

α (alpha)

Best (highest) value found so far for MAX on the path. Starts at −∞. Updated at MAX nodes.

β (beta)

Best (lowest) value found so far for MIN on the path. Starts at +∞. Updated at MIN nodes.

Pruning rule

prune whenever α ≥ β

At a MIN node, stop when its value ≤ α (MAX already has something better elsewhere). At a MAX node, stop when its value ≥ β.

StepNodeWhat happensα, β
1A (MAX)Start−∞, +∞
2B (MIN)Sees 3 → β = 3; sees 12, 8 → no change. B = 3−∞, 3
3AGets 3 from B → α = 33, +∞
4C (MIN)Sees 2 → β = 2. Now α (3) ≥ β (2) → prune 4 and 63, 2
5D (MIN)Sees 14 → β = 14; 5 → β = 5; 2 → β = 2. D = 23, 2
6Amax(3, 2, 2) = 3, choose a1. Same answer as minimax with 2 fewer leaves evaluated.3, +∞

Move ordering matters

  • If D's leaves were ordered 2, 5, 14, alpha-beta would prune after the first leaf (2 ≤ α = 3), saving two more evaluations.
  • Perfect ordering: time O(bm/2), so the effective branching factor becomes √b and alpha-beta can search twice as deep as minimax in the same time.
  • Random ordering: about O(b3m/4).
  • Good ordering in practice: try captures first, then threats, then forward moves; use killer moves and iterative deepening results; store positions in a transposition table.

12Stochastic & partially observable games

Stochastic games (element of chance)

Games like backgammon and Ludo include dice, so MAX cannot know MIN's legal moves in advance. The game tree gets chance nodes (drawn as circles) between MAX and MIN layers, each branch labelled with a probability.

Expectiminimax

EXPECTIMINIMAX(s) = Σr P(r) · EXPECTIMINIMAX(RESULT(s, r)) at a CHANCE node

MAX and MIN nodes work exactly as in minimax. Chance nodes take the probability-weighted average (expected value) of their children.

MAX moveOutcomes (probability → value)Expected value
a10.9 → 2, 0.1 → 30.9×2 + 0.1×3 = 2.1
a20.9 → 1, 0.1 → 40.9×1 + 0.1×4 = 1.3

MAX chooses a1. Now change the leaf values to 20, 30, 1, 400 (same order). a1 = 21, a2 = 0.9 + 40 = 40.9, so MAX now chooses a2. The evaluation function must be a positive linear transformation of the expected utility; in deterministic games only the order of values matters, but with chance the scale matters too.

  • Complexity O(bm nm) where n = number of distinct chance outcomes (21 distinct dice rolls in backgammon), so deep search is impractical.
  • Alpha-beta style pruning is still possible at chance nodes if utilities are bounded.
  • Monte Carlo simulation (rollouts) is a practical alternative: play thousands of random games from a position and average the results.

Partially observable games

Players cannot see the full state, like in the "fog of war".

Kriegspiel

Chess where you see only your own pieces. A referee announces captures and checks. The player tracks a belief state: the set of all board positions consistent with what it has observed.

Card games

Bridge, poker, whist, rummy. Cards are dealt randomly at the start and hidden, so the game is both stochastic and partially observable.

  • Averaging over clairvoyance: consider every possible deal of the hidden cards, solve each as a fully observable game with minimax, and pick the move with the best average value (weighted by the probability of each deal).
  • In practice, sample a few hundred random deals (Monte Carlo) instead of all of them.
  • Flaw: it assumes the hidden information will be revealed after the first move. It never values information-gathering moves or bluffing, and can walk into a gamble it can't win (the classic "road A vs road B" example).
  • A correct approach reasons over belief states, considering what each player knows and how moves reveal information.

★Case studies & scenarios

Try each one on paper first, then open the model answer.

Case 1 · Warehouse robot

A robot in an Amazon-style warehouse moves on a grid (up, down, left, right, cost 1 per move) and must reach a shelf while avoiding blocked cells. Which search algorithm would you use and which heuristic? What changes if diagonal moves are allowed?

Model answer

Formulation: state = (row, column); actions = 4 moves into free cells; goal = shelf cell; cost = 1 per move.

Algorithm: A* with the Manhattan distance h = |x₁−x₂| + |y₁−y₂|. It is admissible (the robot needs at least that many moves even with no obstacles) and consistent, so A* graph search returns the shortest path.

Why not the others: BFS is also optimal here (unit costs) but explores in all directions and uses O(bd) memory; DFS is not optimal and can wander; greedy is fast but can take long detours around shelves.

Diagonal moves: Manhattan now overestimates (one diagonal step covers 2 Manhattan units), so it is no longer admissible and A* may return a sub-optimal path. Use the Chebyshev distance max(|dx|, |dy|) for diagonal cost 1, or the octile/Euclidean distance for diagonal cost √2.

Memory limit on a small controller: switch to IDA*.

Case 2 · Wrong route from a GPS

A navigation app always heads toward the city that is closest in straight-line distance to the destination. A user complains that it took Arad → Sibiu → Fagaras → Bucharest instead of the shorter route. Explain what happened and fix it.

Model answer

The app is using greedy best-first search, f(n) = h(n). It picked Fagaras (h = 176) over Rimnicu Vilcea (h = 193) because Fagaras looks closer, ignoring the 211 km road from Fagaras to Bucharest. Result: 450 km instead of 418 km.

Fix: use A*, f(n) = g(n) + h(n). Straight-line distance never overestimates road distance, so it is admissible and A* returns the optimal 418 km route (see the trace in section 05).

Case 3 · Is this heuristic admissible?

Graph: S→A (1), S→B (4), A→B (2), A→G (12), B→G (3). Heuristic: h(S) = 7, h(A) = 4, h(B) = 2, h(G) = 0. Is h admissible? Is it consistent? What will A* return?

Not admissible, because h(S) = 7 > 6. Not consistent either: h(S) = 7 > c(S,A) + h(A) = 1 + 4 = 5.

Case 4 · University exam timetable

Your college must schedule 40 end-semester exams into 10 slots and 6 rooms. No student may have two exams in the same slot, room capacity must not be exceeded, and a faculty member cannot invigilate two rooms at once. Formulate this as a CSP and explain how you would solve it efficiently.

Model answer
  • Variables: one per exam, E₁ … E₄₀.
  • Domains: pairs (slot, room): 10 × 6 = 60 values each.
  • Hard constraints:
    • If exams Eᵢ and Eⱼ share a student → slot(Eᵢ) ≠ slot(Eⱼ) (binary).
    • Enrolment(Eᵢ) ≤ capacity(room(Eᵢ)) (unary).
    • No two exams in the same (slot, room) → Alldiff on (slot, room) (global).
    • Invigilator not in two rooms in the same slot.
  • Soft constraints: avoid two exams for a student on the same day, heavy subjects not back to back.

Solving: backtracking search with

  • MRV: schedule first the exam with fewest legal (slot, room) pairs left, typically large-enrolment exams that fit only big halls.
  • Degree heuristic: break ties with the exam that clashes with the most other exams (shared students).
  • LCV: try the slot that blocks the fewest options for clashing exams.
  • Forward checking / AC-3 to detect dead ends early.

For very large instances, use min-conflicts local search or simulated annealing starting from a random timetable, with soft constraints in the cost function.

Case 5 · Chess engine under a time limit

You are building a chess program that must make a move within 10 seconds. Minimax on the full tree is impossible. Describe how you would design the search.

Model answer
  1. Depth-limited minimax with a cutoff test instead of the terminal test.
  2. Evaluation function: weighted linear sum of features, e.g. material (P=1, N=B=3, R=5, Q=9), mobility, king safety, pawn structure.
  3. Alpha-beta pruning to search about twice as deep in the same time.
  4. Iterative deepening: search depth 1, 2, 3 … and always keep the best move from the last completed depth, so a move is ready when the 10 seconds end. Previous iterations also give move ordering (best moves first → more pruning).
  5. Transposition table to avoid re-evaluating positions reached by different move orders.
  6. Quiescence search to extend capture sequences and reduce the horizon effect.
  7. Opening book and endgame tables for the start and end of the game.
Case 6 · Ludo AI

In a Ludo app, the AI must choose between two moves. Move X: with probability 1/6 (rolling a six next turn) it reaches a state worth 10, otherwise a state worth 4. Move Y: with probability 1/2 it reaches a state worth 9, otherwise 3. Which algorithm applies and which move should it choose?

Model answer

Dice make the game stochastic, so use expectiminimax with chance nodes.

  • E(X) = (1/6)(10) + (5/6)(4) = 1.67 + 3.33 = 5.0
  • E(Y) = (1/2)(9) + (1/2)(3) = 6.0

Choose Y. Plain minimax would wrongly treat the dice as an adversary and pick the move with the best worst case (X: 4 vs Y: 3), which ignores the probabilities.

Case 7 · Delivery van with 60 stops

A courier company wants a short route visiting 60 drop points once each and returning to the depot. A student suggests A*. Critique this and suggest a better approach.

Model answer

This is the Travelling Salesman Problem (NP-hard). The number of tours is (n−1)!/2 ≈ 10⁸⁰ for n = 60, so A* would run out of memory long before finishing, even with a good heuristic like the minimum spanning tree.

The path of the search does not matter, only the final tour, so local search fits:

  • State = a complete tour; neighbour = a 2-opt swap (reverse a segment of the tour).
  • Hill climbing is fast but gets stuck in local minima; use random restarts.
  • Simulated annealing accepts some longer tours early (high T) to escape local minima and usually gives better routes.
  • Genetic algorithms are another option: tours as chromosomes, order crossover, swap mutation.

A near-optimal route found in seconds is more useful to the business than an optimal one that never finishes.

Case 8 · Poker bot

A poker bot computes, for each possible arrangement of the opponents' hidden cards, the best move as if all cards were visible, and then averages. Why might it play badly?

Model answer

This is averaging over clairvoyance. It assumes that after this move the bot will know all hidden cards, which is false. So it never values actions that gather information (a small bet to see how others react) or hide information (bluffing, randomising play), and it can commit to lines that only work if it could see the cards.

Poker is stochastic and partially observable; a better bot reasons over belief states (probability of each opponent hand given the betting so far) and uses sampling (Monte Carlo) plus game-theoretic mixed strategies.

Case 9 · Unknown depth, tiny memory

A puzzle solver runs on a microcontroller with very little RAM. The solution depth is unknown, all moves cost the same, and the shortest solution is required. Which uninformed algorithm should be used?

Model answer

Iterative deepening DFS.

  • BFS is complete and optimal but needs O(bd) memory, which the device doesn't have.
  • DFS uses O(bm) memory but is not optimal and may go down an infinite branch.
  • DLS needs a known depth limit.
  • IDDFS is complete and optimal for unit costs, uses only O(bd) memory, and its repeated work adds only about 11% for b = 10.

If a good heuristic is available, IDA* is better still.

14Quick revision (2-mark answers)

  • Uninformed search: uses only the problem definition, no domain knowledge.
  • Heuristic h(n): estimated cost of the cheapest path from n to a goal.
  • Admissible: h(n) ≤ h*(n); never overestimates.
  • Consistent: h(n) ≤ c(n,a,n′) + h(n′); implies admissible.
  • A*: f(n) = g(n) + h(n); optimal with admissible (tree) / consistent (graph) h.
  • Greedy best-first: f(n) = h(n); fast but not optimal or complete.
  • IDDFS: DFS memory O(bd) with BFS completeness and optimality.
  • Dominance: h₂ ≥ h₁ everywhere ⇒ h₂ expands no more nodes.
  • Local maximum: peak better than neighbours but not globally best.
  • Simulated annealing: accepts bad moves with probability eΔE/T.
  • CSP: variables X, domains D, constraints C.
  • MRV: choose the variable with the fewest legal values left.
  • LCV: choose the value that rules out the fewest options for neighbours.
  • Forward checking: after assigning, prune neighbours' domains.
  • Arc consistent: every value of X has a supporting value in Y.
  • Minimax: MAX maximises, MIN minimises; O(bm) time.
  • Alpha-beta: prunes when α ≥ β; best case O(bm/2).
  • Horizon effect: pushing an unavoidable loss beyond the search depth.
  • Expectiminimax: minimax plus chance nodes that take expected values.
  • Belief state: set of all states consistent with the agent's observations.
